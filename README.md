# Charity Donation Platform

A mobile charity donation management platform that connects **donors** with **charitable associations**. Associations publish fundraising events, donors contribute to them from their phones, and an **administrator** oversees the whole platform through a dedicated dashboard.

The project is made of a **Flutter** mobile app and a **Spring Boot** REST API backed by **MySQL**.

## Features

### Donors
- Register, log in, and verify their account
- Browse events published by associations
- Donate to an event (amount and/or items)
- View their donation history
- Edit their profile

### Associations
- Dedicated registration and login
- Create, update, and delete events (title, description, location, type, date, time)
- View the list of their events
- Edit the association profile

### Administrators
- Admin dashboard with platform statistics
- Manage associations
- Manage donors (users)

### Platform
- JWT-based authentication with Spring Security
- Password reset with a verification code
- Role-based access (`USER`, `ADMIN`) and a separate association account type

## Getting Started

### Prerequisites

- Git
- JDK 8 or later
- Maven (or use the included `mvnw` wrapper)
- MySQL Server
- Flutter SDK (Dart ^3.6.1) and an Android emulator or a physical device

### 1. Clone the repository

```bash
git clone https://github.com/SalimOmri/charity-donation-platform.git
cd charity-donation-platform
```

### 2. Run the backend

```bash
cd Backend/charity-backend-main
```

Edit `src/main/resources/application.properties` with your own MySQL credentials:

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/charity_db?createDatabaseIfNotExist=true
spring.datasource.username=YOUR_DB_USERNAME
spring.datasource.password=YOUR_DB_PASSWORD
spring.jpa.hibernate.ddl-auto=update
server.port=8080
```

The database `charity_db` is created automatically if it does not exist, and the tables are generated by Hibernate.

Email verification and password reset rely on Spring Mail, so configure an SMTP account as well:

```properties
spring.mail.host=smtp.gmail.com
spring.mail.port=587
spring.mail.username=YOUR_EMAIL
spring.mail.password=YOUR_APP_PASSWORD
spring.mail.properties.mail.smtp.auth=true
spring.mail.properties.mail.smtp.starttls.enable=true
```

Start the server:

```bash
./mvnw spring-boot:run        # Linux / macOS
mvnw.cmd spring-boot:run      # Windows
```

The API is now available at `http://localhost:8080`.

### 3. Run the mobile app

```bash
cd Frontend
flutter pub get
flutter run
```

The app calls the backend at `http://10.0.2.2:8080`, which is the Android emulator's alias for the host machine's `localhost`. If you run the app on a **physical device**, replace `10.0.2.2` in the `baseUrl` values inside the `services/` folders with your computer's local IP address (for example `http://192.168.1.10:8080`), and make sure both devices are on the same network.

## API Overview

| Area | Method | Endpoint | Description |
| ---- | ------ | -------- | ----------- |
| Auth (donor) | POST | `/auth/sign-up` | Register a donor |
| | POST | `/auth/sign-in` | Log in and receive a JWT |
| | GET | `/auth/verify` | Verify an account |
| | GET | `/auth/check-verification` | Check verification status |
| | POST | `/auth/verify-code` | Verify a password reset code |
| Auth (association) | POST | `/auth/association/sign-up` | Register an association |
| | POST | `/auth/association/sign-in` | Log in as an association |
| Users | GET | `/user/all` | List all users |
| | GET | `/user/{id}` | Get a user |
| | PUT | `/user/update/{id}` | Update a user |
| | DELETE | `/user/delete/{id}` | Delete a user |
| Associations | GET | `/user/associations` | List associations |
| | PUT | `/user/associations/{id}` | Update an association |
| | PUT | `/user/associations/update/{id}` | Update association details |
| | DELETE | `/user/associations/{id}` | Delete an association |
| Events | GET | `/api/events/all` | List all events |
| | GET | `/api/events/{id}` | Get an event |
| | POST | `/api/events/add` | Create an event |
| | PUT | `/api/events/update/{id}` | Update an event |
| | DELETE | `/api/events/delete/{id}` | Delete an event |
| Donations | POST | `/api/donations/{userId}/{eventId}` | Donate to an event |
| | GET | `/api/donations/user/{userId}` | Get a donor's donation history |

## Data Model

- **User**: donor or admin account (name, email, phone, gender, date of birth, role, status)
- **Association**: charitable organization account (name, email, phone, status)
- **Event**: fundraising event created by an association (title, description, location, type, date, time)
- **Donation**: contribution from a user to an event (amount, items)
